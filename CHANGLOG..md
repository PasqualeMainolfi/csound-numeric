# Changelog

## [0.1.11] - 2026-09-26

- Fix a slot leak when an opcode with a local handle output re-runs its init pass inside an i-time loop. Each pass re-initialises the same opcode instance, but it took a fresh registry slot every time, and only the last one reached the deinit. The others stayed allocated after the note ended, so the 4096-slot registry filled up across notes and later creations failed with `Invalid handle, registry full`. A local output now releases its previous array when that array was created by the same instance, so the loop keeps reusing one slot
- Leave the previous array alone when a handle reached the local output some other way. A handle copied in with `=` is a reference to another opcode's array, and overwriting the local that holds it no longer frees that array. An operand that is also the output, as in `x = csntranspose(x)`, is still kept alive until the opcode has read it, for local and global outputs alike. Global outputs behave as before: they still release whatever they held
- Fix the same leak for an output that is its own operand in a loop, as in `x = csnadd(x, 1)` repeated in a `while`, local or global. The previous array cannot be freed at creation, because the opcode has not read it yet, so every pass left one orphan behind. The new array now takes it over and releases it on the next pass, or together with itself at the end, which keeps the loop at two slots whatever its length. Only an operand made by the same opcode instance is deferred this way: the first one, made elsewhere and perhaps still owned by a k-rate producer, stays with its owner
- Raise the registry from 4096 to 16384 arrays alive at once. A handle now carries 14 bits of slot index and 18 of generation, up from 12 and 12, so a stale handle is recognised across 262143 reuses of its slot instead of 4095. Compile-time checks make sure every slot index fits the handle and that both fields fit its 32 bits
- Fix a stack buffer overflow in the k-rate *csnindexof*. The k-rate shape bookkeeping always copied `CSN_MAX_DIMS` extents, whatever the rank, and read past the one-element shape buffer of *csnindexof*. The copy now stops at the rank of the array, so the same overflow can no longer happen in any other k-rate producer
- Add an i-time regression for slot reuse: three notes of 3000 looped *csnbuttersos* designs each, more than the registry holds, a `=` alias surviving when its local is overwritten, a local that is both operand and output in a loop, a global `G = csncopy(G)`, and three notes of 3000 accumulating `x = csnadd(x, 1)` passes, through a local and through a global, checked for the final values

## [0.1.10] - 2026-09-26

- Add direct deconvolution, the inverse of a FULL convolution, with a 1-D kernel flat or along one axis and with a kernel shaped like the source (*csndeconvolve1d*, *csndeconvolve*). The convolution sum is run backwards, each output divided by `h[0]` after subtracting what the earlier outputs already explain, so the answer is the quotient `scipy.signal.deconvolve` returns, `x - h + 1` long on each axis. The recurrence is a recursive filter, stable only when the kernel is minimum phase
- Add direct decorrelation, the inverse of a FULL correlation, in the same two shapes (*csndecorrelate1d*, *csndecorrelate*). A correlation is a convolution with the kernel reversed and conjugated, so the recurrence is the same one divided by `conj(h[last])`, and it is stable when the reversed kernel is minimum phase
- Add the Fourier-transform counterparts of the four (*csnfftdeconvolve1d*, *csnfftdeconvolve*, *csnfftdecorrelate1d*, *csnfftdecorrelate*). The spectrum of `x` is divided by `H`, or by `conj(H)` for a decorrelation, whose answer is read `h - 1` into the inverse transform. The transform only has to hold `x`, which is already the FULL answer, so it is the next power of two at or above `x` rather than `x + h - 1`. They have no phase condition, and agree with the direct forms to within rounding whenever `x` really is a FULL convolution or correlation
- Take no `edges` argument on any of the eight: FULL is the only span that keeps everything the source contributed, so it is the only one that can be undone. The axis of the 1-D forms is therefore the third argument, after the trigger on the k-rate overloads
- Reject a source shorter than the kernel, which would have wrapped the output length around, and a zero pivot tap, `h[0]` for a deconvolution and `h[last]` for a decorrelation, which every step divides by
- Reject in the transform forms a kernel whose spectrum has a zero on the transform grid, such as `[1, 1]` at Nyquist or `[[1, 2], [3, 4]]` at Nyquist on both axes, at init or at performance: that bin of the answer is gone, and dividing by what rounding leaves there returned noise in its place. Bins below `1e-12` of the largest count as zeros. The direct forms never look at the spectrum and still answer for such a kernel
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the eight, and their i-time regressions: direct and transform round trips flat, along an axis, N-D and complex
- Add the roots of a polynomial given highest degree first, as `np.roots` takes it, at init only (*csnroots*). Real or complex coefficients; the roots always come back complex and in no set order. With an axis every 1-D slice along it is a separate polynomial, and the output keeps the source's shape with that axis one shorter; without one the last axis is used. They are found together by the Aberth-Ehrlich iteration from a circle bounding every root, and the step is measured relative to the root's size, so large roots converge as readily as small ones
- Reject a *csnroots* slice of length 1, a constant with no roots, and a zero leading coefficient, which `np.roots` strips but which here would put every starting point at infinity; a polynomial the iteration cannot settle in 1000 steps is an init error
- Add the zeros-poles-gain filter transforms of `scipy.signal`, at init only: a lowpass prototype moved to another cutoff, turned into a highpass, a bandpass or a bandstop (*csnlptolpzpk*, *csnlptohpzpk*, *csnlptobpzpk*, *csnlptobszpk*), and an analog filter mapped to a digital one by the bilinear transform (*csnbilinearzpk*). Zeros and poles may be real or complex and come back complex, the zeros may be empty, and the gain is a scalar output. Each takes the same arguments and gives the same roots and gain as its scipy counterpart; the band transforms store the two roots of a pair next to each other
- Reject in the filter transforms fewer poles than zeros, a centre frequency, bandwidth or sampling rate that is not finite and positive, a root at the origin for the highpass and bandstop transforms, and a root at `2 fs` for the bilinear transform, none of which has an image
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the five filter transforms, and i-rate regressions against the scipy formulas: real and complex roots, the zeros added for the excess of poles, every gain, and a prototype with no zeros
- Add the conversion of a transfer function to zeros, poles and gain, as `scipy.signal.tf2zpk`, at init only (*csntftozpk*). The zeros and poles are the roots of the numerator and denominator, found as *csnroots* finds them, and the gain is `b[0] / a[0]` with its sign. Leading zeros are skipped, as `scipy.signal.normalize` strips them, while interior and trailing zeros stay coefficients; a numerator of degree zero gives an empty zeros array. Real coefficients only, and an empty or all-zero numerator or denominator is refused
- Add the *csntftozpk* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regressions: a leading zero stripped, an all-pole filter with a negative gain and a pole at the origin, and an interior zero kept as a coefficient
- Add the expansion of zeros, poles and gain into transfer-function coefficients, as `scipy.signal.zpk2tf`, at init only (*csnzpktotf*). `b = k * poly(z)` and `a = poly(p)`, highest degree first; no zeros gives `b = [k]`. The coefficients are real when the complex roots come in conjugate pairs and complex otherwise, as scipy returns them, with an imaginary part below `1e-12` of the largest coefficient counted as rounding, so the roots *csntftozpk* finds expand back to real coefficients
- Add the *csnzpktotf* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regressions: real roots, a conjugate pair, a lone complex zero giving complex coefficients, an empty zeros array, and the round trip through *csntftozpk*
- Add the lowpass-prototype transforms on transfer-function coefficients, as `scipy.signal.lp2lp`, `lp2hp`, `lp2bp` and `lp2bs`, at init only (*csnlptolp*, *csnlptohp*, *csnlptobp*, *csnlptobs*). They substitute into the polynomials directly, `s -> s / w0`, `w0 / s`, `(s^2 + w0^2) / (s bw)` and `s bw / (s^2 + w0^2)`, expanding the band forms binomially, so no root is ever found: the result is exact up to rounding, a root at the origin is fine for the highpass and bandstop, and a numerator of higher degree than the denominator is accepted. Output lengths and the normalisation, `a[0] = 1` and the leading zeros stripped, follow `scipy.signal.normalize`. Real or complex coefficients
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the four coefficient transforms, and i-rate regressions: each transform of `1 / (s + 1)`, a second-order Butterworth bandpass agreeing with the zeros-poles-gain route, and a highpass of a denominator with a root at the origin
- Add the split of a digital filter given as zeros, poles and gain into second-order sections, as `scipy.signal.zpk2sos` with its default `'nearest'` pairing, at init only (*csnzpktosos*). The result is an `(n, 6)` array of `[b0 b1 b2 a0 a1 a2]` rows: an odd order is padded with a zero and a pole at the origin, poles are taken from the unit circle inwards and paired with their conjugate or the next real pole and with the nearest zeros, the sections closest to the unit circle come last and the gain goes into the first. A complex root without its conjugate is refused; the `'keep_odd'` and `'minimal'` pairings, and with them analog filters, are not available
- Add the *csnzpktosos* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regressions: a single section, the empty filter, an odd order, an all-pole filter ordered by distance from the unit circle, and the product of the sections checked against *csnzpktotf*
- Add the analog Butterworth lowpass prototype, as `scipy.signal.buttap`, at init only (*csnbuttap*): no zeros, gain 1, and the poles `-exp(j pi m / 2N)` in scipy's order, computed symmetrically so the pairs are exact conjugates and the real pole of an odd order is exactly `-1`. The order must be a non-negative integer; 0 gives no poles
- Add the *csnbuttap* reference page, its runnable example, which chains the prototype through *csnlptolpzpk*, *csnbilinearzpk* and *csnzpktosos* into a digital lowpass, the inventory entry, the NumPy correspondence row and i-rate regressions: an odd order with its exact real pole and conjugates, an even order on the unit circle, and order 0
- Add the digital Butterworth filter, as `scipy.signal.butter` with `output='ba'`, at init only (*csnbutterba*): lowpass or highpass from one cutoff, bandpass or bandstop from an array of two, in Hz at a given sampling rate, order first as in scipy. The design is scipy's: the prototype of *csnbuttap*, the cutoffs pre-warped with `2 fs tan(pi f / fs)` so the digital filter is 3 dB down exactly at them, the zeros-poles-gain transform of the type, the bilinear transform, and the expansion into `b` and `a`. The order must be an integer of at least one and the cutoffs must lie strictly between 0 and `fs / 2`, low below high
- Add the digital Butterworth filter as second-order sections, as `scipy.signal.butter` with `output='sos'`, at init only (*csnbuttersos*): the design of *csnbutterba*, paired into an `(n, 6)` array as *csnzpktosos* pairs it. It is the form to use beyond the lowest orders: a sixth-order bandpass from 500 to 700 Hz at 48 kHz is stable as sections and has a denominator root outside the unit circle as `b, a`
- Add digital Chebyshev type I, Chebyshev type II and elliptic filters, as `scipy.signal.cheby1`, `cheby2` and `ellip`, each as transfer-function coefficients and as second-order sections, at init only (*csncheby1ba*, *csncheby1sos*, *csncheby2ba*, *csncheby2sos*, *csnellipba*, *csnellipsos*). They share the Butterworth design and differ only in the analog prototype, ported from scipy's `cheb1ap`, `cheb2ap` and `ellipap`; the elliptic one carries its own complete elliptic integral, Jacobi elliptic functions, Carlson's `R_F` for the inverse `sc` and the nome solution of the degree equation. The arguments are the order and the cutoff, then the ripple `rp`, the attenuation `rs` or both in dB, then the type and the sampling rate. The ripple and attenuation must be positive and finite, an elliptic attenuation must exceed its ripple, and an elliptic order is limited to 64
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the six, and i-rate regressions against the coefficients scipy.signal 1.18 gives for fourteen designs covering every family, type and output form, including the odd-order Chebyshev II and the first-order elliptic special case
- Add filtering with a transfer function and with second-order sections, as `scipy.signal.lfilter` and `sosfilt`, at init, at k-rate and on audio (*csnlfilter*, *csnsosfilter*). Every 1-D slice along the axis, the last by default, runs through transposed direct form II on its own; `b` and `a` are divided by `a[0]` and may differ in length, and every `a0` of a section must be 1. Real or complex data and coefficients, the output complex if either is. At init the filter starts from rest; the k-rate forms keep each slice's state from one pass to the next, so successive blocks filter as one continuous signal, and restart when the number of slices changes; the audio forms take real coefficients and keep their state across control periods. The coefficients are copied at init and may not change afterwards
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of *csnlfilter* and *csnsosfilter*, i-rate regressions against scipy.signal 1.18 (unnormalised `a`, a pure gain, a matrix along each axis, complex data and complex coefficients), and a k-rate and audio regression: three blocks of a two-row signal filtered pass by pass, checked against one call on the whole signal, and the impulse response of both audio forms
- Add filtering from an explicit state, as `scipy.signal.lfilter(..., zi=zi)` and `sosfilt(..., zi=zi)`, at init, at k-rate and on audio (*csnzlfilter*, *csnzsosfilter*). Each call, and each k-rate or audio pass, starts from the state `zi` it is given and returns the final state `zf`, in scipy's layout: the source's shape with the filtered axis replaced by the order, or `(n_sections, ...)` with the axis replaced by 2 for sections. ## [0.1.9] - 2026-09-22

- Add elementwise mapping of a user-defined opcode over an array, in place, driven by a k-rate trigger (*csnforeach*). The callback is a Csound 7 `:Opcode;` object: the orchestra names it with `opcoderef`, allocates it with `create` and wires its argument cells with one `init` call, and it must take one k-rate argument and return one. The array is read flat, so the rank does not matter and the shape is preserved; real arrays only
- Run the *csnforeach* callback with the array registry unlocked, over a copy of the elements taken before the first call and written back after the last, so the callback may call other csnum opcodes without deadlocking on the registry mutex, which is not recursive. A callback that rewrites the same array through another opcode has its writes overwritten by the copy; freeing the array or changing its element type from inside the callback is an error, and a change of size writes back the common prefix
- Reject a *csnforeach* callback that was never created or never wired, that has no performance pass, that does not take exactly one argument and return one, that takes or returns anything other than a k-rate cell, or that was created in a context with a different sample rate or a smaller ksmps. An i-rate or constant cell would otherwise be written through with each element value, and a constant is shared engine-wide
- Add the *csnforeach* reference page, its runnable example, the inventory entry and the NumPy correspondence row; extend the inventory's rate legend with `k` for the opcodes that only act at performance time
- Add the ambisonics coordinate pair, converting between cartesian coordinates and the `(distance, azimuth, elevation)` description of a direction in the AmbiX frame, `+x` front, `+y` left, `+z` up, at init and k-rate (*csncartohoa*, *csnhoatocar*). The elevation is measured from the horizon rather than from `+z`, which is the one thing separating this pair from the spherical one: the two are related by `elevation = pi/2 - theta`, and the pair exists so that the subtraction never has to be remembered
- Add a 3 x 3 rotation matrix constructor, about a basis axis picked by index or about an arbitrary direction held in a handle, at init and k-rate with an optional trigger (*csnrotmat*). The matrices are the mathematical right-handed ones, active on a column vector: composition, the inverse through *csntranspose* and the audio yaw-pitch-roll convention are all built from them rather than baked in, so a constructor meant for plain geometry does not quietly carry an audio sign. The arbitrary direction is normalised internally and the null vector is refused
- Add the composed yaw-pitch-roll matrix, `R = Rz(yaw) * Ry(-pitch) * Rx(roll)`, applied right to left so a source is rolled, then pitched, then yawed (*csnrotmatypr*). It hands back the composed matrix rather than the three factors on purpose: a different order is a different rotation, and composing them by hand is where it goes wrong. The pitch is positive from the front upwards, a rotation about `-y` and not the right-handed `Ry` that *csnrotmat* builds, which is why it carries its own name rather than being a mode of the general constructor
- Add an optional trigger to the k-rate *csnidentity*, after the element type rather than before it: the type was already the second argument, so moving the trigger in front of it would have reinterpreted a call that passes 1 there. It defaults to 1, so a call written before the trigger existed keeps rebuilding on every pass
- Make the angle unit of the six coordinate pairs an i-argument in the k-rate forms as well: it picks how a conversion reads and writes, it is not a value that evolves during a note. A k-rate flag is no longer accepted, which is a breaking change for a call that passed one
- Add ambisonics channel bookkeeping: the ACN index of a component from its order and degree and the pair back, and the channel count of a complete 3-D set of a given order and the order back, at init and k-rate (*csnnmtoacn*, *csnacntonm*, *csnhoaordtochnls*, *csnchnlstohoaord*). A degree outside `[-n, n]` collides with another component's index and is refused, and a channel count that is not a perfect square is refused rather than rounded, because a fractional order is not a smaller set but a set that does not exist
- Add the per-channel gain vectors between the SN3D and N3D normalisations, one value per ACN channel and `(order + 1)^2` long, at init only (*csnsn3dton3d*, *csnn3dtosn3d*). The factor follows the order alone and not the degree, so the vector is constant over blocks of `2n+1` channels and leaves `W` at 1. They answer what to multiply by rather than converting a set themselves, which keeps them numeric and leaves the channel plumbing outside; a normalisation does not change during a note, so there is no performance-time form
- Add reference pages, runnable examples, inventory entries, NumPy correspondence rows and i-rate regression coverage for the channel bookkeeping and the gain vectors, including the round trips in both directions, the refusal of a channel count that is not a complete set, and the reciprocity of the two gain vectors
- Add k-rate regression coverage for the ambisonics pair and the rotation matrices: the trigger holding a result, each yaw-pitch-roll angle driving its own factor, the arbitrary-axis form agreeing with the basis-axis one, and a consumer downstream recomputing because the data version moved
- Add reference pages, runnable examples, inventory entries, NumPy correspondence rows and i-rate regression coverage for the ambisonics pair and the rotation matrices, including the relation between the ambisonics elevation and the spherical inclination, the sign that separates a right-handed rotation about `+y` from the audio pitch convention, and a term-by-term comparison of the composed yaw-pitch-roll matrix against the same product written out by hand
- Add the associated Legendre function `P_n^m(x)`, scalar at init and k-rate and elementwise over a handle of any shape with an optional trigger (*csnlegendre*). It carries no Condon-Shortley phase, so `scipy.special.lpmv(m, n, x)` is `(-1)^m` times it, and the arguments come in the harmonics' order, degree first. A negative order, a non-integer degree, an argument outside `[-1, 1]` and a value that overflows the double range are refused rather than answered with something nearby
- Add the real spherical harmonics of the AmbiX convention, ACN order, SN3D, no Condon-Shortley phase and no `1/sqrt(4 pi)`, with the direction read as *csnhoatocar* reads it: one harmonic at one direction (*csnsphharm*), and every harmonic up to an order at one direction, as a vector of encoding gains, or at many, as a `channels x directions` matrix to build a decoder from (*csnsphharmacn*). The normalisation is carried through the recurrence instead of being divided out afterwards, so no factorial is formed and the values stay within `[-1, 1]` at any order up to 1000. An elevation past the pole is the direction on the other side, and the first order agrees with *bformenc1*
- Add reference pages, runnable examples, inventory entries, NumPy correspondence rows, i-rate regression coverage against values computed independently from Rodrigues' formula, and k-rate coverage for the Legendre functions and the spherical harmonics, including the absent Condon-Shortley phase, the SN3D sum of squares per order, the direction past the pole, and a matrix recomputed after a direction moves
- Add the Lagrange interpolating polynomial through a set of points, returned as its coefficients highest degree first, as `scipy.interpolate.lagrange` hands them to `np.poly1d`, at init only (*csnlagrange*). It goes through the Newton divided differences and Horner's scheme; repeated abscissae are refused rather than answered with infinities
- Add the *csnlagrange* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regression coverage, including a cubic recovered from unevenly spaced points and the one- and two-point cases
- Report a non-square channel count passed to the k-rate *csnchnlstohoaord* as a performance error rather than an init error, and say "greater or equal to zero" in the *csnnmtoacn* message for a negative order, which is what the check has always enforced
- Add an array iterator that hands back one element per control period, walking the array flat, with a state output that is 1 while an element was produced and 0 once the array is exhausted (*csnnext*). Real and complex arrays are two overloads, chosen by the type of the value output, and handing either the other's element type is an init error. An empty array reports a zero state from the first pass
- Take the *csnnext* walk over a copy of the elements made at init, so the iterator answers without holding the registry lock once the array is exhausted; a write to the source while the walk is in progress is refused rather than served from the stale copy, while reading it with other opcodes stays free
- Make the *csnnext* rewind level triggered and zero by default: it restarts the walk on every control period it is high, so it is pulsed rather than held, and the default walk runs once and then reports exhaustion
- Add the *csnnext* reference page, its runnable example, the inventory entry, the NumPy correspondence row and k-rate regression coverage, including the level-triggered rewind, the empty array, the complex overload and the two refusals
- Add k-rate regression coverage for *csnforeach*: one mapping per non-zero trigger, none on a zero trigger, flat traversal of a matrix with its shape preserved, the compounding a second trigger produces, and a downstream k-rate consumer that has to recompute because the data version moved. Two further files pin the callback refusals, an unwired callback and one whose argument is not k-rate, as failure cases matched on their message

## [0.1.2] - 2026-09-14

- Add matrix solving, inversion and determinant on a shared LU decomposition with partial pivoting, real and complex (*csnsolve*, *csninv*, *csndet*)
- Reject singular matrices in *csninv* and *csnsolve* against a pivot threshold scaled to the matrix; *csndet* answers zero, which is what the determinant of a singular matrix is
- Add the Savitzky-Golay coefficient matrix, every derivative order at once, applied with *csncorrelate1d* (*csnsavgol*)
- Add per-note and orchestra-wide real-time marking (*csnrtlockstart*, *csnrtlockend*, *csnrtlockall*), the section between start and end scoped to the note that opened it and closed when that note ends
- Run the moving median on a sliding sorted window instead of sorting every window, and drop the source copy from its in-place form (*csnmovmedian*)
- Add the median filter with scipy's zero-padded edges, along one axis on the same sliding window as the moving median, and over a box of one size per axis (*csnmedfilt1d*, *csnmedfilt*); the kernel is init-time on every overload, so a performance pass allocates nothing
- Fix in-place growth on a real-time path: *csnpush*, *csninsert*, *csnsetinsert*, *csnpad* and *csnresize* reallocated a marked array because the capacity check read a flag registry arrays never carry; the in-place block insert and pad also reallocated the source on every pass
- Fix working buffers growing on a real-time path: they are now reserved at init from the capacity of the array they serve and refused at perf time when that array is marked (moving statistics, median, norm, percentile and quantile, unique, compress, resample, sort, set operations, solve, inverse, determinant, k-rate *csntoarray* and *csnshape*)
- Fix the FFT convolutions on a path marked only through their output (*csnrtlockstart*, *csnrtlockall* or *csnrtlock* on the result): the transform buffers now follow that mark, and a new transform size is refused before *RealFFTSetup* allocates
- Fix a double free in the k-rate N-D FFT convolution, whose inverse work buffer was left aliasing the kernel's, and a wrong allocation check in the 1-D form
- Fix k-rate *csnpad* on a real-time path: the output now starts at the padded shape when the widths are known at init, so passes that keep them need no new storage; it started from the source's shape and was refused on the first pass
- Fix the init-time placeholder of the k-rate *csnpercentile* and *csnquantile* along an axis, which copied the source's element count in bytes rather than elements
- Keep a k-rate output's storage across shape changes that fit it: a producer now takes new storage only when the requested shape outgrows the room it has, twice its initial element count, instead of on every shape change. A marked output can shrink, grow back or change its count with the data (*csncompress*, *csnselect*, *csnunique*, the set operations) on a real-time path; the reused region is cleared, as fresh storage was
- Fix a hang when the k-rate convolutions (*csnconvolve1d*, *csnconvolve*, *csnfftconvolve1d*, *csnfftconvolve*), *csnsolve*, *csninv* or *csndet* raised a performance error, such as an operand freed mid-note: the error was reported with the registry lock held, and the note's deinit then waited on that lock forever
- Add the discrete cosine and sine transforms of types I and II along one axis, each carried by a real FFT over a symmetric extension rather than by the direct sum (*csndctone1d*, *csndcttwo1d*, *csndstone1d*, *csndsttwo1d*); they take their length from the array and accept any of them, since the extension is even whatever the length is, and they run about 1.5x faster than Csound's own *dct*, which extends to four times the length where these extend to two
- Add mel-frequency cepstral coefficients in one opcode, from the STFT through the filterbank and the log to the cepstral transform (*csnmfcc*); the cepstral stage is an explicit coefficients-by-bands table built at init rather than a call into the generic DCT, which at filterbank sizes is both the cheaper transform and the one that places no arithmetic condition on the band count
- Add the triangular mel filterbank as a matrix, linear or logarithmic (*csnmfbank*, *csnmlogfbank*); bands are rows, since adjacent mel bands always overlap and cannot share one
- Build the filterbank triangles at each bin's own centre frequency instead of from rounded bin edges: a band narrower than the bin spacing keeps fractional weight from its neighbours instead of collapsing to silence, which at 128 bands over a 1024-point spectrum was emptying twenty of them
- Cut the FFT copy overhead: a slice already contiguous in the item type the transform wants now moves in one block instead of one strided element at a time, and the scratch is cleared only where zero-padding actually reaches (*csnfft*, *csnrfft*, *csnifft*, *csnirfft* and the 2-D forms). Against Csound's own *rfft* the gap closes from 16-50% to 0-3%
- Add the analytic signal in one and two dimensions and the Hilbert transform on its own (*csnhilbert1d*, *csnhilbert1dr*, *csnhilbert2*); as in scipy the one named for the transform returns the analytic signal, whose real part is the source and whose imaginary part is the transform, and *csnhilbert1dr* answers that imaginary part directly through two real transforms instead of a real one and a complex one, about forty per cent less work
- Take the Hilbert length from the array and never pad it: the transform is global, so a padded length does not extend the answer but changes every sample of it, which is why an odd extent is refused rather than rounded up. There is no real counterpart to *csnhilbert2*, the product mask in two dimensions no longer leaving the real part equal to the source
- Add the Hilbert matrix (*csnhilbertmat*), which shares a name with those and nothing else: 1 / (i + j + 1), the textbook ill-conditioned example, for exercising *csnsolve*, *csninv* and *csndet* where a system is barely solvable
