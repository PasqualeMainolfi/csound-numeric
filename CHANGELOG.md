# Changelog

## [Unreleased]

- Add `CsnStr`, an array of strings with the layout of a `CsnArr`: up to 8 dimensions, a shape and C-order strides, a value that `B = A` copies and that is released with its variable. Every element owns its string, so a copy, a slice or a reload never shares one with its source. It is a type of its own rather than a third element type: the numeric opcodes are declared on `:CsnArr;`, so a `CsnStr` handed to one is refused when the orchestra is compiled instead of reaching code that reads numbers
- Add `:CsnStr;` overloads to *csnempty*, *csnfull* and *csnlike* (a string fill value), *csnfromarray* from an `S[]` and *csntoarray* to one, *csnget* and *csnset*, `v[i][j]`, `v[i][j] = "x"` and `v[i][j] init "x"`, *csngetslice* and `v[start:end, step, axis]`, *csnsetslice*, *csntake* along an axis and flat to an `S`, *csnsize*, *csndims*, *csnshape*, *csnisempty*, *csntype* (which reports `2`), *csnprint*, *csnreshape*, *csnflatten*, *csntranspose*, *csnflip*, *csnroll* and *csnreverse* as a copy or in place, *csnconcat* of two string arrays, *csnstack* of two or more, *csnpush*, *csnpop*, *csninsert* and *csnremove* of one string or a block, *csntruncate*, *csnhead* and *csnresize* (which fills what it adds with `""`) as a copy or in place, *csncopy*, *csnshuffle*, *csnwhere* with a string or a string array for the false branch, *csncompress* and *csnselect* with a real mask, *csnpad* with a string fill value as a copy or in place, *csnk* and *csni* in place or as a copy, *csnrtlock* and *csnrtunlock*. The other elementwise string operations, queries, conversions, sorting and sets come later
- Add *csnstradd*, after `np.strings.add`: it joins two `CsnStr` element by element with NumPy broadcasting, or one `S` after (`csnstradd(a, "x")`) or before (`csnstradd("x", a)`) every element. The result may be an operand, `a = csnstradd(a, "!")`
- Add *csnstrmul*, after `np.strings.multiply`: it repeats each string of a `CsnStr` by one count or by a real `CsnArr` of counts broadcast against it. A count below 0 gives `""`, and a count that is not a whole number (`1.5`, an infinity, a NaN) or a complex array of counts is refused with a message
- Add *csnstrupper* and *csnstrlower*, after `np.strings.upper` and `np.strings.lower`: they change the case of the ASCII letters of every string of a `CsnStr`, as a copy (which may be the source, `a = csnstrupper(a)`) or in place (`csnstrupper(a)`). Every byte from 0x80 up is left as it is whatever the locale, as NumPy does on a bytes (`S`) array, so a UTF-8 string keeps its multibyte characters. A string keeps its length, so the in-place form allocates nothing and runs on a real-time path, and a marked output gets room for the source's longest string at init
- Add *csnstrcapitalize*, after `np.strings.capitalize`: the first character of every string goes up and all the others down, so a string that opens with a digit or a space comes out all lower case. ASCII only, as *csnstrupper*, as a copy or in place, allocating nothing in place
- Add *csnstrswapcase*, after `np.strings.swapcase`: every ASCII letter of every string goes into the other case, and digits, spaces, punctuation and bytes from 0x80 up stay. As a copy or in place; since swapping twice gives the strings back, a k form whose output is its source swaps again on every pass, as `X = csnmul(X, 0.99)` scales again, and its init leaves that case to the first pass
- Add *csnputmask* for strings as `csnputmask(dest, mask, values)`, after `np.putmask`: a real mask cannot hold strings, so unlike the numeric form the destination is a separate first argument. It writes a `CsnStr` of the mask's shape, or one `S`, wherever the mask is non-zero, leaves the other elements alone, and skips an element that already holds its value
- Give the string k forms whose other arguments are strings (*csnlike*, *csnfromarray*, *csntoarray*, *csnload*) an explicit trigger: a string has no i and k forms, so the trigger is what selects the performance overload, and the call without one is the init-time form
- Keep a buffer in every element of a `CsnStr`: a string is written into the buffer of the element that takes it, which grows only for a longer string, and an element emptied by a shrink, a resize or a reused output keeps its buffer for the next one. On an array marked for a real-time path no buffer grows during performance, so a k pass that writes strings runs as long as each string fits the room its element already holds, and the first that does not fit stops it with a performance error naming the opcode and both sizes. The room comes from the init pass: a marked output gets room for the longest string its operands hold there, and *csnstradd*, *csnstrmul* (a k count at its init value), *csnfull*, *csnlike* and *csnpad* size it from the strings they make. Writes in place (*csnset*, `[]`, *csnsetslice*, *csnputmask*, *csnlike*, *csnstradd* or *csnstrmul* onto an operand, the one-string *csnpush* and *csninsert*) check every element first, so a pass that stops changes nothing; a write of the string an element already holds is no write and bumps no version. The k forms of *csnload*, and of *csnpad* and the block *csninsert* in place, which rebuild their strings on every pass, stay refused on a marked array
- Copy a `CsnStr` through the layout opcodes string by string, so the copy never shares a string with its source; reorder one in place (*csntranspose*, *csnflip*, *csnroll*, *csnreverse* without an output, *csnshuffle*, which takes the same draws as a numeric shuffle so a seed permutes both alike) by moving its elements with their buffers, which allocates nothing. *csnpop*, the one-string *csnremove* and *csntruncate* in place move them too: the strings they drop stay with the array past its end, and a later *csnpush* or *csninsert* writes into that buffer. A copying *csnflip* or *csnroll* puts its elements back where the last pass took them before it copies, so each buffer meets the string it held
- Save a `CsnStr` with *csnsave*: to `.npy` as a fixed-width `<U` array, Csound's UTF-8 strings decoded to the code points NumPy stores and padded to the longest element, so `np.load` returns a `str` array; to `.csn` as dtype `3`, each element a byte count and its bytes. A byte that does not start a valid UTF-8 sequence is saved as its own code point, so any string can be written
- Load a `CsnStr` with *csnload* from a `.npy` of dtype `<U`, re-encoded as UTF-8, or `|S`, taken as bytes, in either byte order and in C or Fortran order, and from a `.csn` of dtype `3`. A code point UTF-8 cannot carry is refused, as is a `.csn` byte count that runs past the payload, before anything is allocated
- Refuse a file of numbers loaded into a `CsnStr`, or a file of strings into a `CsnArr`, with a message saying which way round it is, where a string `.npy` used to be reported as an unsupported dtype
- Print a `CsnStr` as `CsnStr(shape=(...), dtype=str)` with every element quoted, as NumPy prints a string array
- Add the reference page [String arrays](doc/string-arrays.md) with a runnable example, the `CsnStr` forms in the opcode pages, a `string` column entry in the opcode index and a string section in the NumPy correspondence; and regressions: creation, reuse and release at k-rate, `[]` and slices, a slice that does not share its strings, layout copies, joins, stacks, takes and pads that do not share theirs, a *csnsetslice* of an array into itself, push, insert, remove and pop reusing the slots past the end, block inserts and removes, truncation and resizing as a copy and in place checked against NumPy, copies that own their strings and a string shuffle that matches the numeric one, masks (*csnwhere*, *csnputmask*, *csncompress*, *csnselect*) and *csnstradd* and *csnstrmul*, in place and with broadcasting, checked against NumPy, *csnstrupper*, *csnstrlower*, *csnstrcapitalize* and *csnstrswapcase* as a copy and in place, checked against NumPy, a k swap onto its own source that swaps once per pass, leaving the bytes past ASCII alone, and an in-place k form that marks its target k-rate so a slice of it follows, k forms on a marked array that run while their strings fit and stop, changing nothing in place, when one does not, checked against NumPy along with in-place reordering and padding, `S[]` round trips, printing, `.npy` and `.csn` round trips at i- and k-rate, and the string loader against `>U` Fortran, `|S`, surrogate and dtype-mismatch fixtures

## [1.0.0] - 2026-10-11

- Fix *csnsavgol* refusing or miscomputing higher orders. The coefficients came from the normal equations, whose conditioning grows so fast with the order that 15/14, 41/20 and even 101/8 were refused as singular, and orders still accepted lost up to 4e-10 of relative accuracy. They now come from a polynomial basis orthonormal over the window (Vandermonde with Arnoldi), exact to a few ulps for every order up to `winsize - 1`, and a failure is reported once instead of three times
- Add *csnloadaudiofile* and *csnsaveaudiofile*: read a `.wav`, `.mp3` or `.flac` file into an array, one row per channel or averaged into one, with the file's sample rate, and write an array as a 32-bit float `.wav`. The k forms act on a trigger, as *csnload* and *csnsave* do. The decoders are dr_wav, dr_mp3 and dr_flac, compiled into the plugin with their symbols kept private
- Make `CsnArr` a value that owns its array, held in the variable's own memory, instead of an id into a plugin registry. `B = A` now copies, a local is freed with its note and a global with the engine, so the registry no longer fills up and no longer holds arrays; it keeps the random generators, the real-time global lock and the mutex
- Remove *csnfree*: nothing is left for it to release
- Add the rate casts *csnk* and *csni*. An array carries its rate, and the operators run at performance time only while one of their operands is k-rate, so an array built from i-rate arguments was updated once, at init. `csnk A` marks an array k-rate in place, from that line on, so that `A += B` accumulates on every control period; `csnk(A)` returns a k-rate copy, retaken only when `A` changes, for one expression at k; `csni(A)` returns a copy frozen at init, the counterpart of `i()`. `csni A` in place is refused on an array that is already k-rate, since the rate only rises. Named opcodes keep choosing their rate by the trigger
- Add operators on `CsnArr`: `+`, `-`, `*`, `/` and `^` between two arrays, an array and an i or k scalar either way round, and an array and a `:Complex;`, the compound `+=`, `-=`, `*=` and `/=`, and unary minus. An operator runs at init, and again on every pass while one of its operands is a k-rate result
- Add `[]` on `CsnArr`: `v[i][j]` reads a real element and writes a real or `:Complex;` one, one index per dimension, and `v[i][j] init x` writes once at init. An access with only i arguments runs once, at init; a k value or index makes it run on every control period, and a k write makes the array k-rate so that the operators on it follow. A complex element is read with *csnget*: Csound types `v[i]` before it knows whether the array is complex
- Add Csound's slice syntax on `CsnArr`: `v[start:end, step, axis]` returns a copy of the range, end included as in Csound's own `slicearray`, a negative or omitted end meaning the last element, along axis 0 unless given. With i bounds it follows a k-rate source; with a k bound it is retaken every control period. *csngetslice* keeps its excluded stop
- Report a wrong number of coordinates to *csnget* and *csnset* as `Expected N indexes, one per dimension, got M`, the message `[]` gives
- Register the opcodes once per Csound instance. Csound can initialise a plugin from the plugin directory twice with the same type pool, which appended every opcode twice; harmless until `[]`, which counts two identical entries as ambiguous
- Split the i-only and the k forms of *csntranspose* and *csnflatten*, in place and not: the k forms take a trigger, and a call without one now transforms once at init
- Write a result over one of its own operands only where that is safe: elementwise opcodes compute in place, the rest refuse it at init with a message naming the operand. A k form whose output is its own operand computes from the first pass, never also at init
- Compute a k form at init only when every argument its result depends on is known there: a constant, an i variable or an array. A k scalar still reads 0 at init, so with one the output is laid out, empty or reserved, and the first pass computes it, where it used to compute from the 0 or publish a copy of the source in its place. *csntoarray* at k-rate accepts such an empty result at init
- Keep an output derived from a reserved-empty source empty as well, as before the migration; *csnconcat* and *csnpad* fill theirs regardless
- Reserve at init what a marked output may need: *csncompress* reserves the whole source, *csnpad* with k widths the shape their init values give. The FFT convolution and correlation follow the output's mark alone, as the resampler does, so *csnrtunlock* on the output now lets their transform grow
- Fix a heap overflow in *csnbuttap* (shapes swapped), *csnlfilter* at k-rate and on audio taking `b` and `a` swapped at init, the k-rate *csnstd*/*csnvar* crashing on a missing destination, the k-rate moving statistics crashing at init, a lock left held by *csnforeach* on an error, and leaks on reinit across several families
- Run the elementwise arithmetic of two real arrays of the same shape, or of a real array and a real scalar, through a dense loop per operation instead of the general broadcast iterator: `+`, `-`, `*`, `/`, `^`, *csnminimum* and *csnmaximum*, named or as operators, in place or not. Against Csound's own array operators at k-rate this takes the sum of two 65536-element arrays from 0.40 to 0.06 of the native time and `C += A` from 2.5 to 0.26
- Pick the operation once, outside the loop, in the elementwise functions of a real array (*csnsqrt*, *csnabs*, *csnexp*, the trigonometric and hyperbolic families, *csnfloor*, *csnceil*, *csnround*, *csndegtorad*, *csnradtodeg* and the rest of the unary family) and in *csnreal*, *csnimag*, *csntocomplex* and *csnconj*. Against Csound's array functions at 65536 elements `sqrt` goes from 0.75 to 0.14 of the native time, `abs`, `floor` and `round` to under 0.1, `sin` and `exp` to about 0.6
- Pick the operation once in the reductions (*csnsum*, *csnmean*, *csnprod*, *csnrms*, *csnmin*, *csnmax*, *csnall*, *csnany* and the subtraction fold, whole array or along an axis), the comparisons and counts (*csngt* and the rest, *csnisnan*, *csnisinf*, *csnisfinite*, *csncnteq*, *csncntnz*, *csncntnan*), *csnmovmin* and *csnmovmax*, and make *csnclip* branch-free. The summation order is kept, so the results do not change. Against Csound at 65536 elements *csnmin* and *csnmax* take 0.51 of `minarray` and `maxarray`, *csnclip* 0.14 of `limit`, and *csngt* drops from 87 to 12 microseconds
- Compute the real *csnstd* and *csnvar* in two passes, the mean and then the squared deviations, as numpy does, instead of Welford's running update, which divides on every element: about 2.8 times faster. Complex arrays keep the running update
- Fix *csnmin* and *csnmax* answering an infinite extreme with the largest finite double: `min([inf])` returned 1.8e308. The fold now starts from the first element. *csnmovmin* and *csnmovmax* had the same seed and now also answer NaN for a window that holds only NaNs, where they returned the largest finite double
- Fix *csnclip* with `min` above `max`: it now computes `min(max(x, min), max)` as `np.clip` does, so every element becomes `max`; a value below `min` used to become `min`
- Fix the k-rate *csncopy* leaving its output at the source's rate: an i-rate source made the result i-rate, so an operator applied to it, `X += Y` among them, never ran at performance time
- End every error message with a line break. Csound 7 no longer adds one after `InitError` and `PerfError` (develop, October 2026), so csnum's messages ran into the next line of the console. They now go through two helpers, `csn_init_error` and `csn_perf_error`, that format the message and end it, with the compiler checking the format against its arguments
- Run the regression suite isolated from an installed csnum, and under AddressSanitizer on macOS through a generated launcher
- Find the prebuilt `version.h` of a Csound source checkout under `platform/android/CsoundAndroid/jni`, where 7.0.0-beta.18 moved it, as well as under the old `Android/` path: the release builds against beta.18 headers stopped at `version.h` not found. The release headers are now pinned to csound develop at 3d4e795, which has `[]` for plugin types (PR #3363)
- Replace `MYFLT` with `cs_float` and the `MYFLT2*` conversions with `CS_FLOAT2*` throughout the sources, following Csound 7, where `MYFLT` is kept only as a deprecated alias and warns on every use. Both name the same type, so the plugin's binary interface is unchanged; the sources now need Csound 7 headers that define `cs_float`

## [0.1.12] - 2026-09-30

- Add real-time Butterworth, Chebyshev type I, Chebyshev type II and elliptic filters on audio whose cutoff follows a k-rate signal (*csnrtbutter*, *csnrtcheby1*, *csnrtcheby2*, *csnrtellip*). The analog prototype is designed once at init, as the `*sos` designs build it; every control period moves it to the current frequencies, pre-warped, maps it by the bilinear transform and rebuilds the second-order sections, then filters the block. Nothing is allocated at performance time. The arguments are those of the `*sos` designs, the cutoff at k-rate and the rest at init
- Take a bandpass or bandstop as a k-rate centre and a k-rate width in Hz, the edges at `fc - bw/2` and `fc + bw/2`, in place of the two-cutoff array of the designs
- Keep the filter state across a moving cutoff: the sections are paired once at init on the prototype, each pole pair with its nearest zero pair from the highest Q down, and a pole pair stays the same section, or the same two in a band, whatever the frequencies. Each section is normalised to unit gain where the prototype's DC gain lands, DC for a lowpass and a bandstop, Nyquist for a highpass, the centre for a bandpass, and the first one carries that gain
- Reject at init an order below one, an elliptic order above 64, a ripple or attenuation that is not finite and positive, an elliptic attenuation not above its ripple, and a type that does not match the cutoff form; reject at performance a cutoff outside `(0, fs / 2)`, a band whose edges leave it, and a width that is not positive
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the four, and audio regressions: the impulse response against the `*sos` design through *csnsosfilter* for lowpass, highpass, bandpass and bandstop at several orders, a cutoff and a band moved during the note that stay bounded and settle on the new design, and the manifest entries

## [0.1.11] - 2026-09-26

- Fix a slot leak when an opcode with a local handle output re-runs its init pass inside an i-time loop. Each pass re-initialises the same opcode instance, but it took a fresh registry slot every time, and only the last one reached the deinit. The others stayed allocated after the note ended, so the 4096-slot registry filled up across notes and later creations failed with `Invalid handle, registry full`. A local output now releases its previous array when that array was created by the same instance, so the loop keeps reusing one slot
- Leave the previous array alone when a handle reached the local output some other way. A handle copied in with `=` is a reference to another opcode's array, and overwriting the local that holds it no longer frees that array. An operand that is also the output, as in `x = csntranspose(x)`, is still kept alive until the opcode has read it, for local and global outputs alike. Global outputs behave as before: they still release whatever they held
- Fix the same leak for an output that is its own operand in a loop, as in `x = csnadd(x, 1)` repeated in a `while`, local or global. The previous array cannot be freed at creation, because the opcode has not read it yet, so every pass left one orphan behind. The new array now takes it over and releases it on the next pass, or together with itself at the end, which keeps the loop at two slots whatever its length. Only an operand made by the same opcode instance is deferred this way: the first one, made elsewhere and perhaps still owned by a k-rate producer, stays with its owner
- Raise the registry from 4096 to 16384 arrays alive at once. A handle now carries 14 bits of slot index and 18 of generation, up from 12 and 12, so a stale handle is recognised across 262143 reuses of its slot instead of 4095. Compile-time checks make sure every slot index fits the handle and that both fields fit its 32 bits
- Fix a stack buffer overflow in the k-rate *csnindexof*. The k-rate shape bookkeeping always copied `CSN_MAX_DIMS` extents, whatever the rank, and read past the one-element shape buffer of *csnindexof*. The copy now stops at the rank of the array, so the same overflow can no longer happen in any other k-rate producer
- Add an i-time regression for slot reuse: three notes of 3000 looped *csnbuttersos* designs each, more than the registry holds, a `=` alias surviving when its local is overwritten, a local that is both operand and output in a loop, a global `G = csncopy(G)`, and three notes of 3000 accumulating `x = csnadd(x, 1)` passes, through a local and through a global, checked for the final values

## [0.1.10] - 2026-09-26

- Add direct deconvolution, the inverse of a FULL convolution, with a 1-D kernel flat or along one axis and with a kernel shaped like the source (*csndeconvolve1d*, *csndeconvolve*). The convolution sum is run backwards, each output divided by `h[0]` after subtracting what the earlier outputs already explain, so the answer is the quotient `scipy.signal.deconvolve` returns, `x - h + 1` long on each axis. The recurrence is a recursive filter, stable only when the kernel is minimum phase
- Add direct decorrelation, the inverse of a FULL correlation, in the same two shapes (*csndecorrelate1d*, *csndecorrelate*). A correlation is a convolution with the kernel reversed and conjugated, so the recurrence is the same one divided by `conj(h[last])`, and it is stable when the reversed kernel is minimum phase
- Add the Fourier-transform counterparts of the four (*csnfftdeconvolve1d*, *csnfftdeconvolve*, *csnfftdecorrelate1d*, *csnfftdecorrelate*). The spectrum of `x` is divided by `H`, or by `conj(H)` for a decorrelation, whose answer is read `h - 1` into the inverse transform. The transform only has to hold `x`, which is already the FULL answer, so it is the next power of two at or above `x` rather than `x + h - 1`. They have no phase condition, and agree with the direct forms to within rounding whenever `x` really is a FULL convolution or correlation
- Take no `edges` argument on any of the eight: FULL is the only span that keeps everything the source contributed, so it is the only one that can be undone. The axis of the 1-D forms is therefore the third argument, after the trigger on the k-rate overloads
- Reject a source shorter than the kernel, which would have wrapped the output length around, and a zero pivot tap, `h[0]` for a deconvolution and `h[last]` for a decorrelation, which every step divides by
- Reject in the transform forms a kernel whose spectrum has a zero on the transform grid, such as `[1, 1]` at Nyquist or `[[1, 2], [3, 4]]` at Nyquist on both axes, at init or at performance: that bin of the answer is gone, and dividing by what rounding leaves there returned noise in its place. Bins below `1e-12` of the largest count as zeros. The direct forms never look at the spectrum and still answer for such a kernel
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the eight, and their i-time regressions: direct and transform round trips flat, along an axis, N-D and complex
- Add the roots of a polynomial given highest degree first, as `np.roots` takes it, at init only (*csnroots*). Real or complex coefficients; the roots always come back complex and in no set order. With an axis every 1-D slice along it is a separate polynomial, and the output keeps the source's shape with that axis one shorter; without one the last axis is used. They are found together by the Aberth-Ehrlich iteration from a circle bounding every root, and the step is measured relative to the root's size, so large roots converge as readily as small ones
- Reject a *csnroots* slice of length 1, a constant with no roots, and a zero leading coefficient, which `np.roots` strips but which here would put every starting point at infinity; a polynomial the iteration cannot settle in 1000 steps is an init error
- Add the zeros-poles-gain filter transforms of `scipy.signal`, at init only: a lowpass prototype moved to another cutoff, turned into a highpass, a bandpass or a bandstop (*csnlptolpzpk*, *csnlptohpzpk*, *csnlptobpzpk*, *csnlptobszpk*), and an analog filter mapped to a digital one by the bilinear transform (*csnbilinearzpk*). Zeros and poles may be real or complex and come back complex, the zeros may be empty, and the gain is a scalar output. Each takes the same arguments and gives the same roots and gain as its scipy counterpart; the band transforms store the two roots of a pair next to each other
- Reject in the filter transforms fewer poles than zeros, a centre frequency, bandwidth or sampling rate that is not finite and positive, a root at the origin for the highpass and bandstop transforms, and a root at `2 fs` for the bilinear transform, none of which has an image
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the five filter transforms, and i-rate regressions against the scipy formulas: real and complex roots, the zeros added for the excess of poles, every gain, and a prototype with no zeros
- Add the conversion of a transfer function to zeros, poles and gain, as `scipy.signal.tf2zpk`, at init only (*csntftozpk*). The zeros and poles are the roots of the numerator and denominator, found as *csnroots* finds them, and the gain is `b[0] / a[0]` with its sign. Leading zeros are skipped, as `scipy.signal.normalize` strips them, while interior and trailing zeros stay coefficients; a numerator of degree zero gives an empty zeros array. Real coefficients only, and an empty or all-zero numerator or denominator is refused
- Add the *csntftozpk* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regressions: a leading zero stripped, an all-pole filter with a negative gain and a pole at the origin, and an interior zero kept as a coefficient
- Add the expansion of zeros, poles and gain into transfer-function coefficients, as `scipy.signal.zpk2tf`, at init only (*csnzpktotf*). `b = k * poly(z)` and `a = poly(p)`, highest degree first; no zeros gives `b = [k]`. The coefficients are real when the complex roots come in conjugate pairs and complex otherwise, as scipy returns them, with an imaginary part below `1e-12` of the largest coefficient counted as rounding, so the roots *csntftozpk* finds expand back to real coefficients
- Add the *csnzpktotf* reference page, its runnable example, the inventory entry, the NumPy correspondence row and i-rate regressions: real roots, a conjugate pair, a lone complex zero giving complex coefficients, an empty zeros array, and the round trip through *csntftozpk*
- Add the lowpass-prototype transforms on transfer-function coefficients, as `scipy.signal.lp2lp`, `lp2hp`, `lp2bp` and `lp2bs`, at init only (*csnlptolp*, *csnlptohp*, *csnlptobp*, *csnlptobs*). They substitute into the polynomials directly, `s -> s / w0`, `w0 / s`, `(s^2 + w0^2) / (s bw)` and `s bw / (s^2 + w0^2)`, expanding the band forms binomially, so no root is ever found: the result is exact up to rounding, a root at the origin is fine for the highpass and bandstop, and a numerator of higher degree than the denominator is accepted. Output lengths and the normalisation, `a[0] = 1` and the leading zeros stripped, follow `scipy.signal.normalize`. Real or complex coefficients
- Add the reference pages, runnable examples, inventory entries and NumPy correspondence rows of the four coefficient transforms, and i-rate regressions: each transform of `1 / (s + 1)`, a second-order Butterworth bandpass agreeing with the zeros-poles-gain route, and a highpass of a denominator with a root at the origin
- Add the split of a digital filter given as zeros, poles and gain into second-order sections, as `scipy.signal.zpk2sos` with its default `'nearest'` pairing, at init only (*csnzpktosos*).
